# Сохранение проектов: первый этап стабилизации

База: `a733a60`. Исправления: `d926dd7`, ветка `codex/engine-stability`.

## Что изменилось

- Сцены, детали и операции ТЗ записываются под общей файловой блокировкой.
  Внутри процесса сохраняется порядок операций. Проверка ревизии и замена
  файла выполняются вместе; старые CLI с `base: updated` совместимы.
- JSON заменяется через уникальный временный файл с синхронизацией записи.
  Предыдущее состояние остаётся в `<id>.json.previous`, для ТЗ —
  `brief.json.previous`. Это одна резервная версия, не история изменений.
  Модели, изображения и прочие вспомогательные файлы этим механизмом не охвачены.
- Создание принимает только разрешённые поля. ID и служебные даты задаёт
  сервер; существующее имя занято даже при повреждённом JSON.
  Изменяющие маршруты проектов/деталей отклоняют посторонний Origin и
  не-JSON тела (кроме двоичной загрузки моделей); JSON ограничен 32 МиБ.
- Редактор сохраняет неподтверждённую сцену в localStorage до отрисовки.
  HTTP-запросы идут последовательно; более новая правка ждёт предыдущего
  подтверждения. Закрытие не полагается на большой keepalive-запрос.
  При следующем открытии предлагается восстановление.
- Копия восстановления относится к тому же браузерному профилю и точному
  origin (протокол, имя хоста, порт). Это не резервная копия между устройствами.
  Ошибки сети и браузерного хранилища видны в существующей строке состояния;
  при отказе обоих хранилищ срабатывает beforeunload.
  Возврат в меню и переход в отчёт не продолжаются после неудачной записи.
  Повторная попытка выполняется при правке, возврате фокуса или событии online.

## Проверено

- `npm run check:project-stability`: два Node-процесса с одной ревизией,
  одновременное создание и операции ТЗ, подмена ID, повреждённое занятое имя,
  резервная копия, ошибка перед заменой файла; очередь автосохранения,
  восстановление большой сцены, отказ localStorage, оба решения конфликта,
  отсутствие crypto.randomUUID в HTTP LAN.
- `node scripts/projectStore.check.mjs` и `node src/brief/brief.check.js`.
- `node scripts/check-camera-persistence.mjs`: 60 циклов, 551 поле снимка.
- `node scripts/check-project-recovery.mjs`: Chromium, настоящий хук и API,
  черновик 137513 байт; закрытие до таймера при заблокированном PUT, повторное
  открытие, восстановление, повторная отправка и чтение с диска.
  В настоящем редакторе проверены правка FOV, статус ошибки, удержание
  страницы после неудачного сохранения и возврат в меню после успешного.
- `npm run lint`, `npm run build`: успешно. Остались прежнее предупреждение
  Fast Refresh в CoastRocksPBR и предупреждения сборки three-globe/размера чанков.

Все сценарии записи выполнялись на временном доме данных и отдельном кеше,
в свежем профиле браузера на 41213. Пользовательские проекты не изменялись.
Закрытие Electron, полное GPU smoke и физический телефон отдельно не проверялись.

Оставлены следующему этапу: полнота копирования проекта и запись генплана
в preview=1 (пункты 5–6 исходного ревью). Старые запущенные серверы и CLI
нужно перезапустить из обновлённого чекаута: чужой процесс без новой
блокировки не участвует в протоколе записи.
