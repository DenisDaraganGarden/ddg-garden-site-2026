# Освещение сада и электрика — решение (2026-09-25)

Световой проект участка: светильники светят сцену ночью, у каждого — тип,
наведение, яркость и подключение; под ними — слой питания (щитки, цепи,
трассы и траншеи), который считается функциями, а не пишется руками.
Агент (Claude / Codex в чате) собирает композицию и предлагает питание через
эти функции; Денис правит в редакторе; движок держит связи и расчёт.

Всё здесь — предварительная схема для проектирования. Выпуск электрики для
монтажа — после проверки специалистом по исходным данным и нормам региона.

## Слои

| Слой | Что | Где |
|---|---|---|
| Композиция | светильники: тип, место, наведение, яркость, «почему здесь» | `lightingFixtures` |
| Питание | щитки, цепи (напряжение, автомат, кабель), подключение светильника к цепи | `lightingPanels`, `lightingCircuits`, `fixture.circuit` |
| Управление | протокол цепи и прибора (выкл., DALI, DMX, 0–10 В, Casambi); группы и сценарии — позже | `circuit.control`, `type.control` |
| Прокладка | траншеи и кабели — **считаются** при каждом открытии; хранятся только закреплённые участки | `lightingRuns` (закреплённые), `electric.js` |

Вычисленное (трассы, длины, нагрузки, падение напряжения, ведомость) в проект
не пишется — как посадки цветника (`fillBed.js`), оно одинаково выходит из
данных. Поэтому перенос щитка или замена прибора сразу пересчитывают свободные
трассы, а закреплённые (`lightingRuns`, `locked`) остаются как были: если они
больше не сходятся — это конфликт, который показывается, а не молча чинится.

## Рендер: световое поле, а не источники three.js

Источники three.js не годятся: каждый — итерация в каждом освещённом пикселе,
счёт входит в ключ программы (добавить или убрать один — пересобрать все
шейдеры), и на Metal/ANGLE упираются в лимит униформ на десятках.

Световое поле (`src/lighting/lightField.js` + `gardenLightShader.js`):

- Все светильники — строки float-текстуры (4 текселя на свет: позиция и
  дальность; ось луча и строка профиля; цвет × сила; запас).
- Участок в плане — сетка клеток; клетка хранит до `K = 16` индексов светов,
  которые до неё достают (с учётом конуса и дальности). Пиксель берёт свою
  клетку по мировым x, z и перебирает только её список. Цена пикселя
  ограничена `K` и не зависит от общего числа приборов; добавление, перенос,
  замена — это перезапись текстур, без пересборки шейдеров.
- Дальность света — где освещённость падает до ~0,3 лк; на краю — окно
  three.js `(1 − (d/r)⁴)²`, поэтому швов между клетками нет.
- Профиль силы света — строка текстуры профилей (128 отсчётов по углу от оси
  луча 0…180°), общая для типа: из IES/LDT паспорта или из «люмены + угол
  луча + форма» (`photometry.js`).
- Встраивается туда же, где движок добавляет тени облаков: единая точка
  `applyCloudShadowShader` (оба пути — CSM и без CSM), цикл вставлен перед
  `#include <lights_fragment_maps>` и зовёт `RE_Direct` — материал отвечает
  своим PBR (диффуз, блик GGX, стекло). Мировая точка пикселя
  восстанавливается из `viewMatrix`, поэтому свет верен и в отражении воды,
  и в кубе стекла. Для вырезанных карточек (`USE_ALPHATEST`: растения,
  2D-деревья модели) — просвет листа с обратной стороны.
- Не получают поля: собственные `ShaderMaterial` (вода, небо), Lambert/Phong,
  `MeshBasic`. В «Участке» воды нет.
- Тени (`gardenShadows.js`) — атлас глубины 4096² (256 плиток по 256²):
  спот — одна плитка перспективы по оси луча, широкий свет — грани куба,
  которых касается конус (боллард вниз — пять). Плитка — глубина от
  светильника: модель, посадки, лианы, изгороди, деревья (листва и 2D-деревья
  по вырезу, стекло тени не даёт); рисуется, когда свет переставили или
  сцена изменилась, по шесть плиток за кадр и только ночью. В шейдере — та же
  камера плитки (базис по оси, «вверх» — мировой Y), логарифмическая глубина
  движка переводится в метры, четыре соседних текселя — мягкий край, точка
  сдвинута к свету на полтора текселя. Вырезанная карточка (крона) себя не
  затеняет — запас 2,5 м: в карте теней она развёрнута к светильнику, в кадре
  к камере. Не влезшие в атлас светы — без тени (сильные раскладываются
  первыми). Выключатель — `lightingShadows`.

**Единицы.** Сцена не физическая по абсолютным числам (солнце к луне ≈ 64:1),
поэтому один коэффициент: `E_сцены = 0,2 · E_лк`, т. е. сила в сцене =
0,2 · кд. При ACES и альбедо 0,3: 2 лк ≈ 55/255, 10 лк ≈ 138, 30 лк ≈ 206 —
дорожка в 10 лк читается светлой плиткой, лунная земля ≈ 18. Ручка
«Экспозиция света» (EV) сдвигает это без изменения данных. Цвет — CCT в
линейный sRGB с яркостью 1.

**Включение.** `lightingMode`: `auto` — фотореле, по ночному весу неба
(`sky.night`); `on`; `off`. Яркость прибора (`dim`) — в данных света.

**Ночь.** Дневной HDRI («studio») ночью светит сцену как ~5 лк и глушит сад;
`hdriAtNight` — доля HDRI ночью (1 — как было; для проектов со светом ~0,05).

## Типы и библиотека

Встроенные заготовки (`src/lighting/types.js`) и изделия библиотеки
(`~/Ouroboros/library/luminaires/<id>.json`, как растения) — одна форма:

```js
{
  id, ru, en, maker?, model?, article?, url?,
  housing: { shape: 'bollard'|'spike'|'inground'|'wall'|'step'|'post', h, d, w?, color, metal, rough },
  optics: { lumens, beam, field?, cct, cri?, profile: 'spot'|'flood'|'lambert'|'bollard'|'updown'|'omni', ies?, tilt? },  // tilt — поворот оптики от нормали, °
  mount: 'ground'|'wall'|'pole', pitch,              // наведение по умолчанию, градусы (−90 — вниз, 90 — вверх)
  power: { watts, volts: 230|24|12, current: 'ac'|'dc', driver: 'integrated'|'remote', pf?,
           perBreaker?: { B10?, B16?, C10?, C16? }, inrush?: { amps, micros } },
  control: ['switch'|'dali'|'dmx'|'0-10v'|'casambi'],
  ip?, ik?,
  price?: { rub, at, date, url },                    // цена за штуку: где и когда её видели
  source: { 'optics.lumens': 'sheet'|'denis'|'guess', ... },  // происхождение полей; нет поля — неизвестно
}
```

Картинка изделия — `library/luminaires/<id>/photo.webp` (фото с сайта
производителя или своё, до 1200 px; `POST|DELETE /__library/luminaires/<id>/photo`,
в записи — `photoVersion`). Без неё превью — схема корпуса по числам записи
(`LuminaireGlyph`: форма, высота, угол и наклон луча, цвет света).

**Рабочее место** «Освещение → Светильники» устроено как «Растения»:
инструменты (Светильник O, Навести, Щиток, Сверху), карточка выбранного и
вкладки — «Обзор» (итоги, состав по видам, расставленные), «Библиотека»
(виды — по форме корпуса, `LUMINAIRE_KINDS` в `fixtures.js`, они же дают
букву номера; производитель — переключатель; карточка изделия с паспортом,
ценой, ссылкой и тем, что угадано; «Ставить» и «Заменить выбранный») и
«Спецификация» — `luminaireSchedule` (`fixtures.js`), та же, что в отчёте
проекта: по видам, марки, штуки, мощность, цены, итог и «Копировать для
Excel». Считается при каждой правке расстановки.

`housing.h` — высота корпуса; у грунтового — глубина закладки (не рисуется,
над землёй всегда кольцо 15 мм). Наводимые — спот и грунтовый: луч ходит в
пределах `optics.tilt` (у грунтовых по умолчанию 20°, оптика поворачивается
внутри корпуса), видимая голова — в пределах того, что держит её геометрия.

«Вот такой внешний вид» — заготовка с `guess`. «Вот этот прибор в закупку» —
артикул, исполнение и паспорт (`sheet`). Из фотографии фотометрия и
подключение не выводятся — такие поля остаются `guess` и видны в ведомости.
Отделка экземпляра, которой нет у завода, — `finish` светильника, помечается
как авторский вариант; отделка, свечение линзы и фотометрия настраиваются
раздельно.

## Данные проекта (`src/lighting/settings.js`)

Проектные ключи (как окружение и материалы: не публикуются, в снимки камер не
входят — на сайте библиотеки нет):

```js
lightingEnabled: true,
lightingFixtures: [{ id, type, x, y, z, nx, ny, nz,   // точка крепления и нормаль поверхности
                     yaw, pitch,                       // ось луча, градусы; yaw 0 — к +Z
                     target?: [x, y, z],               // навести на точку (дерево, фасад) — ось считается
                     dim, circuit?, note?, by: 'agent'|'denis', locked?, finish? }],
lightingPanels:   [{ id, name, x, y, z, yaw, note?, by, locked? }],
lightingCircuits: [{ id, name, panel, volts, current, breaker?, section?, control, note? }],
lightingRuns:     [{ id, points: [[x, z]], kind: 'trench'|'wall'|'conduit', note? }],   // закреплённые
lightingSurfaces: { '<материал SketchUp>': 'lawn'|'paving'|'deck'|'bed'|'roots'|'building'|'water'|'open'|'unknown' },
lightingSite:     { depth, slack, tail, drop, supply?: { x, z, known, note } },
lightingMode: 'auto', lightingExposure: 0, lightingConnections: false,
```

## Электрика (`src/lighting/electric.js`, чистые функции)

- Сетка участка 0,5 м (`siteGrid.js` строит её в браузере из треугольников
  модели, цветников, таблицы покрытий и крон): цена клетки — газон 1,
  мощение 3, настил 2, цветник 8, зона корней 5, здание и вода — нельзя,
  неизвестное — отдельно помечено.
- Цепь — дерево Штейнера от щитка по клеткам (эвристика кратчайших путей:
  присоединять ближайший неподключённый прибор к уже построенному дереву).
  Цепи по очереди; клетки, где траншея уже есть, дешевле (одна траншея —
  много кабелей). Закреплённые участки — траншея с самого начала.
- Длина кабеля цепи = рёбра дерева + подъёмы (опора, фасад) + глубина
  траншеи на каждом выходе + запас на концы + процент слабины.
- Ток по каждому участку дерева — сумма приборов ниже по течению;
  ΔU = 2·ρ·L·I/S по участкам (ρ меди при рабочей температуре 0,0225
  Ом·мм²/м), в процентах от напряжения цепи — для 12/24 В решающее.
- Сечение — наименьшее стандартное, при котором ΔU ≤ предела и допустимый ток
  ≥ номинала автомата; автомат — по току цепи с запасом. Число драйверов на
  автомат — только по таблице паспорта (`perBreaker`), иначе «не проверено».
  УЗО 30 мА для наружных цепей — пометкой.
- Конфликты: прибор недостижим; напряжение или управление прибора не как у
  цепи (после замены); ΔU выше предела при любом сечении; закреплённый участок
  не используется или не доходит до щитка; прибор без цепи; превышение по
  таблице автомата.

## План работ

1. Свет в сцене: поле, корпуса, свечение линз, ночь; инструмент
   «Светильник» (поставить, навести, заменить, яркость).
2. Электрика: щиток, цепи, автотрассы с общими траншеями, расчёт, слой
   «Подключения», конфликты, ведомость в отчёте, `scripts/lighting.mjs` для
   агента.
3. Управление (группы, сценарии), IES/LDT, тени главных приборов, стены по
   плану, гирлянды и линейные источники.
