# Назначение материалов по граням — 26 сентября 2026

Работа выполнена в `codex/material-workbench`, в чекауте
`infallible-diffie-462766`, на который указывает установленный OUROBOROS.
Пользовательские проекты, библиотека и опубликованная сцена не записывались.

## Поведение

- `B` включает материалы и открывает панель без обязательного первого выбора.
  Один щелчок выбирает связанную плоскую грань SketchUp, включая её треугольники;
  `Shift` добавляет/снимает грани. Выделение видно в сцене.
- «Применить к» задаёт область: грани, элемент/компонент либо весь исходный
  материал внутри выбранной модели. Панель показывает путь текущей цели и число
  выбранных частей. Выбор узла в дереве модели переключает цель на этот элемент.
- Окно, выбранный образец, аналоги и незавершённая подготовка сохраняются при
  переходе к другой цели. Назначение нескольким целям — одна операция истории.
  Восстановление снимает назначение только с выбранной области.
- Кисть изгороди перенесена на `Shift+B`, подписи обновлены. Пробел по-прежнему
  открывает большой просмотр материала.
- Новое назначение использует общие координаты модели: соседние плоские части
  не начинают текстуру каждая со своего нуля. Доступны поворот и сдвиги U/V в метрах.
  Для целого материала остаются исходные UV SketchUp.
- Процедурный фальц при назначении выбирает «Вдоль ската»: продольные швы идут
  вниз по наклонной плоскости, физический размер не сжимается плановой проекцией.
  Режим можно выбрать вручную для любого материала.

## Устройство и сохранение

`useMaterialEditor` отделяет выбор цели от жизненного цикла MaterialPanel.
`selection.js` собирает связные копланарные треугольники и сохраняет адреса mesh
в исходной иерархии glTF, ID ассета и номера исходных треугольников. Общие геометрии
у копий компонентов не делают их общей целью. Перегруппировка треугольников при
назначении хранит обратные номера для следующего клика.

Правила проходят общий нормализатор `modelMaterials`, живут в проекте/снимке
камеры и применяются существующим пайплайном материалов. Выбор не мутирует
исходную геометрию. Адреса от другого файла модели не применяются к новому ассету.
Наложение выбора не участвует в picking, скрывается вместе с объектом и освобождает
свои GPU-ресурсы. Правила одинакового вида объединяются без изменения порядка
относительно прежних правил по направлению грани.

## Проверено

На копии актуального Ростова 2, отдельном origin 41213 и свежих профилях:

- В Chrome: открытие по B без цели, выбор отдельных граней, Shift по двум разным
  исходным материалам, применение гальки, сохранение выбранного образца при
  переходе на соседнюю грань, применение ко всему компоненту, отмена и reload.
  Соседние невыбранные поверхности сохранили свои материалы.
- В отдельном Electron: два ската одной крыши, назначение фальца по Shift,
  индивидуальное направление швов на каждом скате и неизменные соседние скаты.
- `check:ai-materials`, `modelResources.check.js`, ESLint изменённых файлов,
  production build. Сборка сохраняет прежнее предупреждение о больших chunks.

## Границы

- Связная плоская поверхность определяется по топологии импортированного glTF.
  Отдельные исходные полигоны SketchUp, сваренные экспортом в одну плоскость,
  восстановить без исходных face ID нельзя. Криволинейная поверхность состоит
  из нескольких выбираемых плоских частей.
- Общая проекция выравнивает плоские соседние детали. Это не универсальная
  развёртка через произвольные сгибы; фаза на перпендикулярных торцах может
  потребовать сдвига. Модельные оси используются как вертикаль/горизонталь.
- Несовпадающие края самой картинки остаются видны даже при правильных UV.
  У существующего «Самшита» в библиотеке `seam: none`; его изображение не меняли.
  Для него нужна явная обработка шва в подготовке материала.
- Перенос отдельных назначений при замене модели с другой топологией не добавлен.
  Большие многотысячные наборы граней, мобильный GPU и длительный сеанс отдельно
  не измерены. Push и публикации не выполнялись.
