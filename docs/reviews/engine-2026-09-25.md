1. **[P1] Последняя правка теряется при закрытии или перезагрузке до автосохранения.**  
   [useHomeSceneSettings.js:1532](/Users/denisdaragan/Documents/Not0-Not1/2026/DDG-buro/Syte/.claude/worktrees/infallible-diffie-462766/src/features/home-scene/hooks/useHomeSceneSettings.js:1532)

   Сохранение откладывается на 700 мс; обработчик `pagehide` отменяет таймер и отправляет весь снимок с `keepalive: true`. В Chromium большой запрос не проходит. У проверенного нормализованного проекта тело запроса составляло примерно 138 КБ, при лимите keepalive 64 КиБ.

   Воспроизведение с настоящим хуком и локальным API: изменение `planeHeight` на 0.125 после ожидания автосохранения попало в файл; изменение на 0.25 и переход со страницы через 50 мс оставили в файле 0.125. Отдельная проверка транспорта: 1024 байта дошли до сервера, 138382 байта дали `TypeError: Failed to fetch` и до сервера не дошли.

   Нужен надёжный механизм сохранения перед уходом: ожидание обычного запроса там, где переход контролируется приложением, и локально сохранённая очередь несинхронизированных изменений для закрытия/сбоя. Один `keepalive` не защищает эти сцены. Кнопка возврата в меню уже вызывает `flushProjectSave`, но перезагрузка, закрытие окна и команда меню Electron обходят эту кнопку.

2. **[P1] Создание записи допускает подмену ID и выход из папки проектов.**  
   [projectStore.mjs:123](/Users/denisdaragan/Documents/Not0-Not1/2026/DDG-buro/Syte/.claude/worktrees/infallible-diffie-462766/scripts/projectStore.mjs:123)

   В `create({ name, from, ...rest })` поле `rest.id` накладывается после безопасного ID, полученного через `freeId`. Затем `write` использует этот ID как путь без проверки. Через создание можно также перезаписать существующую запись, обойдя проверку `base`.

   В изолированном хранилище `id: '../review-escaped'` создал JSON рядом с папкой `projects`. Через HTTP тот же маршрут принял POST с `Content-Type: text/plain` и посторонним `Origin`, ответил 200 и создал контрольный файл вне `projects`. Это проверка серверного обработчика; прохождение запроса из внешнего сайта через браузерные ограничения доступа к локальной сети отдельно не проверялось.

   Поля создаваемой записи надо брать из разрешённого списка, а ID генерировать и проверять на сервере; запись должна оставаться внутри каталога хранилища. Для изменяющих локальных маршрутов также нужна единая проверка источника запроса.

3. **[P1] Проверка версии сцены не защищает от одновременных сохранений.**  
   [projectStore.mjs:137](/Users/denisdaragan/Documents/Not0-Not1/2026/DDG-buro/Syte/.claude/worktrees/infallible-diffie-462766/scripts/projectStore.mjs:137)

   Чтение файла, сравнение `base` и запись разделены асинхронными операциями. Два окна редактора или редактор и агент могут прочитать одну версию, оба пройти проверку и записать разные полные сцены. Общий дом данных используется разными процессами, поэтому одной очереди внутри Vite недостаточно.

   Воспроизведение: два одновременных `projects.save` с одинаковым `base` вернули успех, конфликтов — 0; на диске осталось только одно из изменений. Существующая проверка хранилища проверяет последовательную устаревшую запись и этот случай не охватывает.

   Чтение, проверку версии и запись следует выполнять под общей для процессов блокировкой либо через единственного владельца хранилища; заменять файл атомарно и гарантировать новую ревизию для каждого сохранения.
